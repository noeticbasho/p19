## Context

ADR 0007 adopted `AGENTS.md` and deliberately added no `CLAUDE.md` pointer for Claude Code,
which reads only `CLAUDE.md`: a one-line shim is "a second file whose only job is to not
drift". It named the follow-up: "If Claude Code auto-loading ever matters here, add the shim
then, as a compatible follow-up."

On 2026-10-28 the repository joined the studio's AIWG workspace (root `../aiwg`), whose
members are developed with Claude Code. The project owner chose, for every member, AIWG's full
Claude Code deployment with `AGENTS.md` loaded into it (decided while onboarding
`ADSI/infrastructure`, the first member). AIWG generates a `CLAUDE.md` of its own — framework
context and skill routing — so the file exists either way; the question is only whether it
loads `AGENTS.md`.

## Decision

1. `aiwg use all --provider claude` generated `CLAUDE.md` (AIWG-managed), `AIWG.md`,
   `WORKSPACE.md`, `.claude/` (26 skills, hooks; the existing `settings.local.json` kept) and
   `.aiwg/` (SDLC pages derived from this repository's records).
2. `CLAUDE.md` starts with `@AGENTS.md`, outside AIWG's managed block, so Claude Code loads
   this file in full at session start. `AGENTS.md` stays the only guidance document: nothing
   in `CLAUDE.md` restates it, so there is nothing to drift.
3. AIWG's `PermissionRequest` auto-approve hook is removed from `.claude/settings.json` (it
   approves by command prefix); `WORKSPACE.md` records that a redeploy may add it back.

## Alternatives considered

- **No `CLAUDE.md` (ADR 0007 as written).** Claude Code would start without this file or the
  workspace's context; rejected now that Claude Code is the workspace's harness.
- **A hand-written one-line shim.** What 0007 rejected; moot, since AIWG generates the file.
- **Let AIWG generate `AGENTS.md` too.** It would replace this hand-written document; never
  allowed (`WORKSPACE.md`).

## Consequences

- Claude Code sessions load `AGENTS.md` (~55 KB) automatically; other AGENTS.md-reading
  harnesses (opencode, omp) are unaffected.
- `CLAUDE.md` is regenerated by `aiwg regenerate`; the `@AGENTS.md` line sits outside the
  managed block so it survives. `aiwg regenerate --force` is never run here.
- `.aiwg/` pages are derived from `AGENTS.md`, the ADRs, bug reports and playtests; those stay
  authoritative.
