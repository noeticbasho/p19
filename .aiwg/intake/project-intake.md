## System Overview

A Bevy 0.19 3D multiplayer game prototype built "always multiplayer": even singleplayer runs a local client and server. A headless authoritative server (`p19-server`: levels from `.glb` with Avian colliders, players, movement, combat, spawning) and a client (`p19-client`: rendering, UI on bevy_markup, input, camera, VR) agree through `p19-shared` (replication registration, messages, bundles, states). Networking is lightyear 0.30 over UDP/netcode with per-client tokens over TLS; movement is server-authoritative with optional client prediction through bevy_ahoy. Steam Deck is the minimum-spec target. The studio's agent-playtesting method started here (ADRs 0009–0012; 51 playtest reports), and bevy_mcp_harness was extracted from it.

## Problem and Outcomes

- Prove an always-multiplayer architecture (authoritative server, prediction, rollback, interest management) on Bevy.
- Develop it with agents that playtest the real game headlessly and file bugs and reports.
- Run on Steam Deck with identical content across hardware.

## Architecture (Current State)

Cargo workspace with three members; the server is headless and authoritative, the client sends intent and renders replicated state. Details: @AGENTS.md ("Architecture: client / shared / server", "Dependency layout").

## Scale and Performance (Current)

A few clients per server in playtests; Steam Deck (~4 GB VRAM) is the budget, met with KTX2/BC6H assets. No load testing.

## Security and Compliance (Current)

- Netcode tokens issued over TLS with a self-signed, TOFU-pinned certificate: dev-grade; production needs a CA-signed certificate on a real backend.
- The agent tool API is behind the `dev-tools` feature, localhost only.
- Code MIT OR Apache-2.0; original assets CC0 (ADR 0018).

## Team and Operations (Current)

One developer with AI agents (omp with GLM, opencode, Claude Code). ADRs, bug reports, playtest reports per run. CI builds the server and a shippable steamrt4 client; it runs no tests. Commits go straight to `main`.

## Known Issues and Technical Debt

From `AGENTS.md` "Known gaps": disconnected players never cleaned up; all players spawn at one point; no level switching; the only level renders black; no NPC input path; replay movement mismatch; no ground friction; VR grip poses likely untracked; dev-grade netcode; dead code and five unused dependencies; a handful of unit tests.
